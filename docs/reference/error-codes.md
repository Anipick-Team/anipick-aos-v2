# 커스텀 API 에러 코드

백엔드가 `ApiResponse.code`로 내려주는 비즈니스 에러 코드 전체 목록. `code == 200`이 아니면 전부 실패이고, 앱은 이걸 `DataError.Network.Api(code, message, reason)`로 받는다 — `message`는 `ApiResponse.value`(서버가 내려주는 노출 메시지 그대로), `reason`은 `ApiResponse.errorReason`이다. (`core/network/HttpClientExt.kt`, `core/common/result/DataError.kt`)

새 코드가 추가되면 이 표에 이어서 추가한다. QA 테스트케이스([`qa-testcase-format.md`](../conventions/qa-testcase-format.md))의 "실패 케이스"/"실패 시 UI" 칸을 쓸 때 이 표를 근거로 삼는다.

## 이 문서를 QA 케이스에 쓸 때 주의할 점

- **노출 메시지는 대부분 서버가 내려주는 그대로 화면에 꽂힌다** — 클라이언트가 코드별로 문구를 하드코딩하는 게 아니라 `error.message`를 스낵바/인라인 텍스트에 그대로 표시하는 화면이 많다. 그래서 이 표의 "노출 메시지"는 "현재 서버가 이 코드에 실제로 내려주는 문구"이자 "그대로 화면에 뜨는 문구"인 경우가 대부분이다.
- **일부 코드는 코드 자체를 보고 분기해서 메시지 대신 다른 동작(다이얼로그, 자동 로그아웃 등)을 한다.** 지금까지 코드에서 실제로 `code`를 분기하는 곳은 아래 "클라이언트 처리" 칸에 표시해뒀다. 그 외 코드는 화면마다 실제로 `error.message`를 렌더링하는지 아니면 그냥 버려지는지(=아무 UI도 안 뜸) 화면의 `ViewModel.onFailure`/`Screen.kt`를 직접 확인해야 한다 — 이 표만 보고 "이 문구가 뜬다"고 단정하지 말 것.
- 코드 자체가 아니라 인프라 레벨(타임아웃, 네트워크 없음, 알 수 없는 예외)은 이 표에 없고 `DataError.Network`의 다른 case(`NO_INTERNET`, `UNKNOWN` 등)로 따로 온다.
